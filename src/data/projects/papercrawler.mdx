## The Problem Space

Reading dense ML papers is hard. Metrics, datasets, and key results are buried in prose, and most readers lack the time to parse every section. **PAPER CRAWLER** turns a paper into a guided walk: a spider crawls top-to-bottom, highlighting metrics, numbers, and datasets as it goes, while Gemini explains each section in plain English. When the model returns the one phrase that matters (`KEY: 28.4 BLEU`), the spider runs to that phrase and boxes it.

## Core Features

### The Spider

- **IK legs + tetrapod gait**: a canvas spider with inverse-kinematics legs that walks the paper from top to bottom.
- **Markup brain**: metrics glow, numbers blow up, datasets get boxed, key phrases highlighted - all painted with `::before` bars so the page never reflows under the spider's feet.
- **Steerable**: click anywhere to send it there, or drop it again with `D`.

### Paper Library

- **Your papers**: everything in `papers/`, searchable by title, id, or author.
- **Add a paper**: type an arXiv id or URL (`1706.03762`, `https://arxiv.org/abs/1810.04805`) - the server downloads it from arXiv and streams progress back.
- **Table of contents**: click a section and the spider sprints there; the explainer picks the section up on the way.

### AI Explainer

- **Plain English**: Gemini explains each section in under 70 words, with a `KEY:` line naming the one phrase that matters.
- **Three levels**: beginner (CS freshman), student (knows basic ML), researcher (precise and technical).
- **Explain a selection**: select any passage and press `E`.
- **Crawler Notes**: metrics, models, and datasets the spider touched.
- **Export**: download a Markdown breakdown or the notes as JSON.

### Remembers You

- **Resume**: the paper, the reading level, the scroll position, and the section the spider was in are kept in `localStorage`, so opening the app drops you back where you were.
- **Shareable URL**: `?paper=1706.03762&level=researcher`.

### Safe by Default

- **Key stays on the server**: `GEMINI_API_KEY` is read from `.env` and never reaches the browser.
- **Static allowlist**: only `index.html`, `css/`, `js/`, and `papers/` are served - `.env`, `cache/`, and `serve.py` return 404.
- **Content-Security-Policy**: a downloaded paper can show its figures but cannot run its own scripts.

## Architecture

The spider's frame loop is strict: **read → update → draw → commit**. Nothing in `update`/`draw` touches the DOM; every write is queued and applied in `commit`, so the page never reflows under the spider's feet.

```
spider enters a section
  -> crawler emits "section"             (binary search over heading positions)
  -> Analyst.onSection() queues a job    (one request at a time)
  -> POST /api/explain {title, section, text, level}   (serve.py holds the key)
  -> serve.py streams Gemini's answer back as SSE       (typed out live)
  -> the last line is "KEY: <exact phrase>"
  -> we find that phrase in the paper and send the spider to it
```

## Tech Stack

### Backend

- **Python standard library only** (`http.server`, `urllib`, `json`, …) - no pip, no virtualenv.
- **`serve.py`**: static host, `/api/explain` (Gemini proxy, SSE streaming), `/api/fetch` (arXiv download, SSE progress), `/api/papers`, `/api/status`.
- **Model pool**: a chain of Gemini models with automatic fallback, quota parking, and cooldowns.

### Frontend

- **Vanilla JS ES modules** - no framework, no bundler.
- **`loader.js`**: cleans the arXiv HTML, lazily wraps words, indexes sections.
- **`crawler.js`**: IK legs, tetrapod gait, the markup brain.
- **`spider-draw.js`**: canvas painting only.
- **`analyst.js`**: the Gemini panel, Crawler Notes, Markdown/JSON export.
- **`library.js`**: the paper drawer.
- **`main.js`**: wiring + keyboard + "where you left off".
- **`css/style.css`**: LaTeXML theme + the `.m-*` markup effects.

## Quick Start

### Prerequisites

- Python 3.9+
- A Gemini API key (free from https://aistudio.google.com/)

### Installation

1. **Clone the repository**

    ```bash
    git clone https://github.com/aridepai17/PAPER-CRAWLER.git
    cd PAPER-CRAWLER
    ```

2. **Add your API key**

    ```bash
    echo "GEMINI_API_KEY=your-key-here" > .env
    ```

3. **Run it**

    ```bash
    python3 serve.py
    ```

    Open http://localhost:5173. The drawer opens on its own - type an arXiv id (e.g. `1706.03762`) and press Enter.

### Pre-download a paper from the terminal

```bash
python3 fetch_paper.py 1706.03762
python3 fetch_paper.py --batch "1706.03762 2005.14165"
python3 fetch_paper.py https://arxiv.org/abs/1810.04805
```

No dependencies, no build step.

## Usage

### Adding a Paper

Open the library drawer (`L`), type an arXiv id or URL, and press Enter. The server downloads the HTML and metadata from arXiv, rewrites the figure URLs to absolute addresses, and the paper appears in your library.

### Reading

The spider drops onto the paper and walks down it, marking up the words it passes. It emits a `section` event on each new section, which queues a Gemini explanation. Switch levels with `B` / `S` / `R`.

### Jumping to a Section

Open the drawer (`L`) and click any entry in "this paper". The spider sprints there and the explainer picks the section up on the way.

## Keyboard Shortcuts

| key         | what it does                                             |
| ----------- | -------------------------------------------------------- |
| `L`         | library: your papers, the table of contents, add a paper |
| `Space`     | pause / resume the spider                                |
| `F`         | camera follow                                            |
| `T`         | title caption                                            |
| `1` `2` `3` | markup intensity                                         |
| `B` `S` `R` | explain at beginner / student / researcher level         |
| `E`         | explain the selected passage                             |
| `C`         | clear the markup                                         |
| `D`         | re-drop the spider                                       |
| `?`         | the keyboard list                                        |
| `Esc`       | close the drawer / the help                              |

`?debug=1` shows the IK skeleton, the foot targets, an FPS counter, and exposes `window.__crawler` / `window.__analyst` in the console.

## API Documentation

### Endpoints

- `GET /api/papers` - list of downloaded papers (reads `papers/*.json`).
- `GET /api/status` - `{"hasKey": bool, "model": "...", "quotaReset": 0}`.
- `POST /api/explain` - ask Gemini to explain a section, streamed as SSE.
- `POST /api/fetch` - download a paper from arXiv, streamed as SSE progress.

### SSE Messages (`/api/explain`)

- `{"type":"text", "text":"..."}` - a chunk of the answer.
- `{"type":"reset"}` - a model died mid-answer.
- `{"type":"done", "cached":bool, "model":"..."}` - finished.
- `{"type":"error", "code":"...", "message":"...", "resetAt":...}` - failure.

## Security

- **Authentication**: none needed - it is a single-user local tool.
- **API key**: read from `.env`, never sent to the browser, never logged.
- **Static files**: allowlist on the _resolved_ path, so `../` tricks can't reach `.env` / `cache/` / `serve.py`.
- **Content-Security-Policy**: a downloaded paper can show its figures but cannot run its own scripts; the page cannot be framed.
- **Host binding**: `127.0.0.1` by default - do not bind to `0.0.0.0` without adding authentication.
